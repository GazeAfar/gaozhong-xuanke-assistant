# 高中选科助手 决策与待定事项

版本：0.1　日期：2026年11月25日

## 已确认约束

| 编号 | 事项 | 文档执行方式 |
| --- | --- | --- |
| C01 | 产品名高中选科助手，微信小程序 | 围绕家长快速选科比较建立文档 |
| C02 | 轻量、少操作、快速出结果 | 六科短表单，可选内容可跳过 |
| C03 | 基础测算和核心报告免费 | 全部候选、理由、对比、重测无广告门槛 |
| C04 | 探索微信流量主变现 | 功能可在未开广告时完整运行 |
| C05 | 激励广告或轻游戏只能可选 | 不进入核心路径；首版不安排游戏 |
| C06 | 先完善文档，再开发 | 本轮产出开发前文档，不提前编写产品业务代码 |

## 建议方案

| 编号 | 方案 | 建议理由 | 调整影响 |
| --- | --- | --- | --- |
| D01 | 江苏首发，架构预留省份 | 数据与规则维护范围可控 | 改全国首发会增加政策库和验收工作 |
| D02 | 六科优势自评，兴趣可选 | 首次操作短，不误算高考赋分 | 改成绩输入需重写比较口径和表单 |
| D03 | 优势 65% 兴趣 35% | 提供可解释的初始比较机制 | 非验证参数，试用后可调整并升版本 |
| D04 | 原生小程序 TS 加本机引擎 | 降低运行成本，保护填写信息 | 若改跨端框架需重新评估平台能力 |
| D05 | 云开发维护公共专业库 | 减少自建基础设施 | 需核对账号、费用、SDK 与权限 |
| D06 | 不建账号，本机记录 | 减少登录阻力和数据收集 | 暂无跨设备同步 |
| D07 | 蓝白灰的清晰工具风格 | 让家长容易阅读和操作 | 可以在开发前更换视觉方向 |
| D08 | 首版广告关闭，后续末尾单一广告位 | 先验证使用价值和流程 | 不影响核心免费要求 |
| D09 | 维护脚本替代完整管理后台 | 首发维护事项有限 | 以后多人编辑时再评审后台 |

上述均是待评审建议，不把先前助手提出的方案等同于用户已确认决定。

## 优先评审的事项

第一优先是确认 D01、D02、D04：首发江苏是否符合范围，是否接受用简短自评作为首版输入，以及是否采用原生小程序技术路线。这些决定会改变页面、算法和开发任务的主干。

其次评审权重、配色、本机记录和广告阶段。此类事项可以在体验版试用后调整，但应保留版本与变更原因，不能在发布后无记录地改变既有报告。

| 项目 | 当前状态 | 解决方式 |
